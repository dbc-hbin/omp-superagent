# omp-superagent 0.1.16

- HEAD supports `/head /superstack <task>` on a Host with a compatible managed omp-superkit revision. `/head /superstack` and `/head /superstack off` wait for the Host to become idle, then change the current HEAD branch without starting work. Command selection is pinned at admission, and HEAD confirms a toggle only after reading back the native branch state. Superstack does not create a goal or become a lane workflow.
- Discord can place new lane threads in a different eligible parent in the same guild when `discord.allowCrossChannelThreads` is enabled. Placement stays in the source parent by default. The optional `discord.crossChannelThreadScope` defaults to `"allowlist"`; `"guild"` permits eligible unlisted destinations without granting them request, command, approval, or history access.
- Discord adds the configured owner to bot-created work threads. Scoped work-thread continuations and approvals stay bound to their original authorized routes.

**Before upgrading**, follow the [upgrade procedure](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.16/docs/OPERATIONS.en.md#update-an-existing-installation) ([한국어](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.16/docs/OPERATIONS.md#기존-설치-업데이트)). Use the old installation to stop affected resident lanes and Gateway/HEAD and verify their exits. `stop main` alone does not stop independent lanes. Keep the original config and journals, install `omp-superagent@0.1.16`, and restart only previously running Gateways.
