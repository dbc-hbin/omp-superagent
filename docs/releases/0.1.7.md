# omp-superagent 0.1.7

- **Control the Discord bot’s online indicator from chat.** Ask the bot to stay online, show its presence, or turn the indicator off without disconnecting it. The response distinguishes the requested setting from the value sent on the current connection; neither proves what a remote user sees. Slack Socket Mode bots and Telegram bots cannot use this control (#35).
- **Watch a PR or its CI from the original conversation.** Give HEAD a GitHub PR URL or `owner/repo#number`. The first check establishes a baseline; later changes notify the registering conversation. The default interval is five minutes. A watch never merges a PR or retries CI (#35).
- **Watch a managed lane without changing its work.** Request notifications for recorded progress, holds, failures, or closure. Stopping notifications does not pause or cancel the lane, and silence alone is not reported as a stall (#35).
- **Shorter CI.** The release gate runs the SDK-matched stock OMP on Ubuntu and macOS. OMP 18 remains available for manual compatibility checks; all four native package install checks remain required (#35).
- **Use the SUPER workflow names.** Start an authorized request with `super`, `super-plan`, `super-run`, `super-loop`, `super-research`, or `super-graph`. These are the public commands in [omp-superkit](https://github.com/dbc-hbin/omp-superkit/commit/c11a6e4e185f9c31f484a05a13528ef724337bc1); quoted examples and lane reports do not select a workflow.
- **Run a lane on an enrolled SSH worker.** The head can open a lane at an approved checkout revision and reconnect to the same OMP session. Approvals and results stay on the original conversation. Enrollment requires confirmation on both machines; no system SSH server or background GUI launcher is installed. See the [worker setup guide](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.7/README.md#add-a-remote-worker) (#31, #34).
- **Check worker enrollment and connectivity.** `omp-sa worker list --config FILE` reads the local inventory without connecting. `omp-sa worker doctor USER@HOST[:PORT] --config FILE` diagnoses the enrolled destination. For a non-default port, enroll with that port and verify the corresponding `[host]:port` host key (#34).
- **Address the bot explicitly in shared Discord channels.** Set `discord.requireAddressing` to `true` to accept an owner message in a shared parent channel only when it mentions the bot or replies to a verified bot message. The default is unchanged. Owner DMs and authorized threads do not require a mention; an edit or reconnect does not elevate a restricted room to owner authority (#34).
- **Continue on the right thread.** Follow-ups in bound threads continue their existing work. New requests go to HEAD, which can use scoped memory and verified session history without replaying held work or transferring approvals (#28).
- **Keep the selected OMP memory backend.** An enabled native backend is preserved. When memory is off or unset, the integration defaults to Mnemopi only when the selected profile can be safely updated (#27).

Thanks to [Jay (@Momentum96)](https://github.com/Momentum96) for the original Discord addressing filter [#29](https://github.com/dbc-hbin/omp-superagent/pull/29) and the proposals for [remote lane parity (#30)](https://github.com/dbc-hbin/omp-superagent/pull/30), [worker diagnostics (#32)](https://github.com/dbc-hbin/omp-superagent/pull/32), and [macOS GUI workers (#33)](https://github.com/dbc-hbin/omp-superagent/pull/33). The GUI launcher is not part of this release.

## Install or upgrade

```sh
bun add --global --trust omp-superagent@0.1.7
omp-sa --help
```

Alternatively, use `npm install --global omp-superagent@0.1.7` with Bun 1.4.4 or later on `PATH`. The package includes the Host owner and Gateway for macOS and Linux on arm64 and x64. Running managed sessions requires a separately installed OMP.
