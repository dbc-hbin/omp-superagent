# omp-superagent 0.1.8

- **Follow up without `/steer`.** An ordinary owner reply can join the active HEAD or lane run in the same conversation at OMP's next steering boundary. A different thread does not interrupt it. History searches no longer delay the durable receipt; later messages stay ordered within their conversation. Replies to unrelated destinations can be delivered independently (#41, #45, #47).
- **Reset a specific account, or let the HEAD queue recover.** `/usage reset` lists available resets without spending one. Select an account and confirm to use one reset. Separately, after a verified Codex quota refusal with no tool calls or partial answer, fresh account and usage evidence can release the HEAD queue. This cancels the failed input rather than replaying it and never spends a reset (#36, #38).
- **Choose how far external PR intake can go.** Read-only PR watches are unchanged. An owner who enrolls a personal repository with `/cron pr-add` in an authorized Discord parent channel opts into tool-free static review and a GitHub comment. Fix commits and protected merges require a higher mode or a fresh command for the reviewed SHA. Older discovery-only registrations stay manual. Read the [PR intake guide](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.8/docs/OPERATIONS.md#새-외부-pr-검토-cron-pr-add) before enrolling a private repository (#46).
- **Discord addressing and progress.** With `discord.requireAddressing` enabled, ordinary owner messages in threads created by someone else need a bot mention or a reply to the bot, just like shared parent channels. Bot-created threads and owner DMs keep their existing behavior. Set `discord.editProgressInPlace` to edit one progress message per request; the default keeps separate posts, and the final answer is always separate. Reports render tables as labeled rows, supported cards as embeds when permitted, and lane titles reflect the final state (#37, #39, #40, #48).
- **Scheduled shell commands are disabled.** Use `/cron add` for scheduled HEAD prompts with normal approval checks. Legacy direct-shell jobs can be inspected or removed but are not run, replayed as prompts, or allowed to send pending shell output. Check any previously started shell job on its original host before resolving it (#44).
- **OMP and Host startup.** CI and the published SDK now use stock OMP **19.1.1**. Hosts check the installed CLI's capabilities rather than requiring an exact version. Startup reuses unchanged CLI inspection and combines discovery with preparation. Preset changes are monitored without reloading unchanged settings, including when a watched configuration is replaced on macOS (#42, #43).

Thanks to [@gimso2x](https://github.com/gimso2x) and [@Momentum96](https://github.com/Momentum96) for contributions to this release.

## Install or upgrade

```sh
bun add --global --trust omp-superagent@0.1.8
omp-sa --help
```

Alternatively, use `npm install --global omp-superagent@0.1.8` with Bun 1.4.4 or later on `PATH`. The npm package includes the native Host owner and Gateway for macOS and Linux on arm64 and x64. OMP is installed separately. Installing the package does not restart a running Gateway.
